# Product Perspective Analysis — Pipeline Flow

## 核心结论

**当前状态：MVP 可走通，但用户心智模型缺一环。**
创建 → 部署 → 查看运行结果 这个链路通了，但每个环节都有「我刚刚做了什么？」的认知断层。

---

## 1. 从头问到尾的那个问题：「部署成功就等于跑了吗？」

这就是最大的产品缺口。用户点了部署 → 弹出成功 → 然后呢？

**用户当前的心理路径：**
```
拖组件 → 连线 → 点部署 → "部署成功" → ❓ 跑了吗？怎么看日志？它在哪里？
```

**根本原因：**
- 用户没有「提交 workflow → Argo 执行 → 等待结果」这个心智模型
- "部署"这个词暗示的是「发布」，不是「运行」
- 部署成功后没有引导用户去监控页

**产品建议：**
- 部署成功后弹窗增加「查看运行状态」按钮（已有点击查看，但需要更主动）
- 文案改为「已提交运行，正在分配资源…」而不是「部署成功」
- 默认 3 秒后自动跳转到工作流详情页（带返回入口）

---

## 2. 工作流的「黑盒」感

用户说「我想看这个节点的日志，能否看得到？」

**现状：代码层面能看日志，但现在有三个问题：**

### 2a. 命名失真
| 画布上的名字 | Argo 里显示的名字 |
|-------------|-----------------|
| Pass Through (节点1) | step-step-1 |
| Python Script (节点2) | step-step-2 |
| Pass Through (节点3) | step-step-3 |

Argo 用的是 Argo 内部 ID，用户完全对应不上。

**建议：** 把 `step-{index}` 改为用户画布上设置的节点名称，或者至少保留映射关系。

### 2b. 日志可见性
日志功能已经实现但入口深：工作流列表 → 点查看 → 选节点 → 切日志 Tab

**建议：**
- 工作流增加「快速查看日志」入口（不需要进详情页）
- 日志应该能看到完整流程（所有节点的日志按时间线排列）
- 日志流应该实时（对于 Running 状态的工作流）

### 2c. 节点状态不直观
DAG 视图展示 4 个节点，但用户画布只拖了 3 个。多出来的那个是 Argo 的 DAG root 节点。

**建议：** 过滤或特殊标记 DAG root 节点，不让用户困惑。

---

## 3. 页面导航的跃迁感

当前切换路线：
```
仪表盘 → 流水线（新建） → 部署 → 流水线运行（列表） → 点查看 → 详情页
```

每步都是整页跳转。用户在「创建」和「查看结果」之间来回切，缺少上下文连续感。

**建议（按优先级）：**
- P1: 部署成功后自动刷新工作流列表（而不是空手返回）
- P2: 部署到工作流的导航更流畅（可从部署弹窗直接跳转）
- P3: 考虑在新的 tab/侧边栏打开

---

## 4. 组件生态太薄

只有 2 个组件（Pass Through, Python Script）。用户只能：
- 用 busybox 跑个空命令
- 用 python 跑脚本

**缺失的能力：**
- 无法配置节点参数（环境变量、命令、资源限制）→ 需要点击「选择一个节点进行配置」
- 没有组件模板市场
- 无法传参数/变量给流水线（仅支持 asset_ids）

**建议：** 尽快开放节点配置面板，让用户可以设置命令、参数、环境变量。

---

## 5. 可观测性的空白

Argo Workflow 提供的能力（后端已有 API），但前端还没接上：

| 能力 | 后端 | 前端 | 建议优先级 |
|------|------|------|-----------|
| 日志查看 | ✅ | ✅ 代码完成 | P0 — 已验证，可用 |
| 节点状态 | ✅ | ✅ | P0 |
| 运行节点数 | ✅ | ✅ | P0 |
| 停止工作流 | ✅ (StopWorkflow) | ❌ | P1 |
| 重试工作流 | ✅ (RetryDeployment) | ❌ | P1 |
| 事件日志 | ✅ (ListWorkflows) | ✅ | P0 |
| 工作流 YAML 查看 | ✅ (Manifest) | ❌ | P2 |
| 实时状态推送(SSE) | ❌ | ❌ | P2 |

**当前工作流列表页有一条 Error 的记录 `my-pipeline-e1cba5`，用户点击 Error 看到详情但没有明确的「为什么会失败」提示。**

---

## 6. 产品路线建议

### Phase 1（立刻 — 补心智模型断裂）
- ✅ 部署成功 → 自动引导看运行状态
- ✅ 节点命名映射（画布名 → Argo 显示名）
- ✅ 节点配置面板可用（参数、命令、环境变量）

### Phase 2（快速 — 补齐可观测性）
- 停止/重试功能
- 自动刷新工作流状态（Running 的自动轮询）
- 日志查看的节点名对应

### Phase 3（迭代 — 提升 UX）
- 模板管理和版本化
- 排期支持（cron schedule）
- 工作流配置的 asset 绑定
- 多 run 对比视图

## 总结一句话

**功能链路跑通了，但每步之间的「认知过渡」没做好。用户能到终点，但不知道自己到了终点，也不知道中途发生了什么。**
