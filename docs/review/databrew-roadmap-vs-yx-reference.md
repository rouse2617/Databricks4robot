# Databrew 发展路线图 — 对标 yx 参考架构

> 基于卓驭科技（原大疆车载）计算平台组公开文档（yx-files）与 cyber-databrew 当前状态的对比分析。
> 
> **核心判断：** databrew 当前处于"资产平台"阶段，yx 参考架构展示了"Data+AI 一体化平台"的终态。
> 以下路线图分三期，每期都有明确的产出和接入条件。

---

## 一、参考架构概述（yx）

卓驭数据平台的整体分层：


## 五、关键风险与建议

1. **别贪大求全** — yx 文档是一个成熟团队（~15人）几年的积累，databrew 现阶段聚焦资产平台，二期再扩展
2. **Pipeline 是瓶颈** — 所有后续能力（产线、模型训练）都依赖 pipeline 稳定，建议优先推进合入 dev
3. **血缘是分水岭** — 没有血缘，数据平台只是"资产管理器"；有了血缘，才能说"数据平台"。建议第一期至少跑通基础血缘（录入+展示），第二期做深度
4. **统一 Catalog 不着急** — 当前资产都在 BigLake Iceberg 上，多数据源联邦检索的需求还没出现，Q4 再说
5. **版本管理要先做** — 没有版本管理，资产回滚、对比、追溯都是空谈，而且阻塞后续血缘和模型管理
