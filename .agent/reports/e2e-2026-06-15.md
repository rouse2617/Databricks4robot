## 二、清场任务详情

### 任务 1：删除孤儿执行记录 `e2e-mcp-20260615-001-32a8d0`

**问题描述**：删除流水线模板时，后端**未级联删除**关联的执行记录，导致孤儿运行记录遗留。

**操作步骤**：
1. 导航到 `/pipeline?tab=executions`
2. 找到记录 `e2e-mcp-20260615-001-32a8d0`（状态：Failed，创建时间 2026-06-15 00:13:35）
3. 点击「more 操作」→「删除」→ 确认对话框点击「删 除」
4. 验证：执行记录总数从 **8381 → 8380**

**关键发现**：
- 前端 MCP 工具的 `click` 在 dialog 上的按钮时有竞态（uid 刷新）；改用 `evaluate_script` + DOM 查询成功
- UI 删除入口存在（执行记录支持删除），无需 DB 直连
- 截图工具因 protocolTimeout 偏短偶发超时，改用 JS 直接操作 DOM

## 三、a11y 修复详情

### 任务 2：修复 form 字段缺 id/name（a11y issue count: 6 → 已修复部分）

**问题来源**：Chrome DevTools Console `[issue] A form field element should have an id or name attribute (count: X)`

**修复文件**：`Frontend/src/pages/WorkflowExecutionList.tsx`

**修复内容**（共 4 个表单元素 + 1 个已存在）：

| 元素 | 原状态 | 修复后 id |
|------|--------|-----------|
| 状态筛选 Select | ❌ 无 id | `workflow-execution-status-filter` |
| 模板版本筛选 Select | ❌ 无 id | `workflow-execution-version-filter` |
| 按名称搜索 Input | ✅ 已有 id | `workflow-execution-name-search` |

**Linter 验证**：`ReadLints` 无报错，TypeScript 类型检查通过。

**剩余未修复**：控制台可能还有少量遗留（来自其他页面，如 BatchJobList、ComponentManager 等），本次仅示范修复 `ExecutionRecordsPanel` 对应的 `WorkflowExecutionList.tsx`。

## 五、发现的 Bug 与问题

### Bug 1：保存流水线会触发后端自动运行（重要）
- **严重程度**：⚠️ 高
- **描述**：创建脏名流水线 `e2e-mcp-20260615-002-2step0260615-002-2step` 后，保存时后端**自动触发了一次运行**（执行 ID `e2e-mcp-20260615-001-32a8d0`，Failed），并非用户主动点击「运行」
- **复现步骤**：
  1. 在「流水线」tab 创建新流水线（输入脏名称）
  2. 点击「保存」
  3. 观察：后端自动下发了一次执行，状态为 Failed
- **推测原因**：`savePipeline` 或保存流程中有副作用调用了 `deployPipelineForAssets`

### Bug 2：删除模板不级联删除运行记录（孤儿记录）
- **严重程度**：⚠️ 中
- **描述**：删除流水线模板后，关联的执行记录仍然保留在 `executions` 表中
- **已验证**：本轮成功通过 UI 手动清理了一条孤儿记录
- **建议**：后端在删除模板的 API 中加入 cascade delete，或前端提供批量清理工具

### Bug 3：a11y — form 字段缺 id/name
- **严重程度**：⚠️ 低（可访问性问题）
- **已修复**：见第三节
- **剩余**：可能还有来自其他页面的表单字段未修复
