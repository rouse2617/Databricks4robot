## 2026-07-06 — Skip new mock-based unit test, rely on live deploy verification

- **Context**: tasks.md calls for a unit/integration test covering "backfill batch item deployed for a job with a known creator". `executeItem` calls `uc.pipelineUC.DeployByTemplateID`, a concrete `*pipelineUC.Usecase` method (not interface-based DI), which requires a working `templateRepo` to avoid a nil-pointer panic on `FindByID`. Every existing backfill-package test that constructs a `pipelineUC.Usecase` passes `nil` for `templateRepo` (confirmed via grep) — none of them exercise this path, meaning covering it properly would require building a new `PipelineTemplateRepository` mock (plus tracing `Deploy()`'s further dependencies) from scratch.
- **Decision**: skip building that new mock scaffolding. Verify the fix via the live deploy-verification step already required for this change (submit a real backfill batch as an authenticated user on dev, `kubectl get pod ... -o jsonpath='{.metadata.labels}'`) instead of a new unit test.
- **Alternatives**: build a minimal `PipelineTemplateRepository` mock to unit-test `executeItem` directly.
- **Rationale**: the fix is a single struct-field copy (`Owner: job.CreatedBy`) with no branching logic — the risk a unit test would catch is near-zero. The bug this change fixes was itself an omission that a "does it compile" check would never catch; the live E2E check is strictly stronger evidence for this exact bug class (proves the value reaches the real deployed pod, not just that a mock captured a struct field) and is required anyway per the deploy-before-commit gate. Building new mock infrastructure disproportionate to a one-line fix was judged not worth the added surface area to maintain.
