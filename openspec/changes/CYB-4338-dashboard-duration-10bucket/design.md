# CYB-4338 design

## 为何 10 桶 "前密后疏"(而非等距细拆)

只读 SELECT 实证 dev 的真实分布(总和 18209):
```
<1m 727 | 1-5m 5207 | 5-10m 2001 | 10-15m 1025 | 15-20m 758
20-25m 612 | 25-30m 3006 | 30-45m 4873 | 45-60m 0 | 60m+ 0
```
- 质量集中在 1-30min,故高频区 5min 等距细拆(把老"1-10min=7208"拆出 1-5m 尖峰)。
- 长尾(30-60min)15min 等距即可(45-60m/60m+ 实测为 0);不必再细。
- P50(15m44s)落 15-20m 桶、P90(30m1s)落 30-45m 桶 —— 桶边界贴合关键分位。

边界(ms)与 model/SQL 锁死:
`60000/300000/600000/900000/1200000/1500000/1800000/2700000/3600000/+`

## 为何 ECharts(而非修 flexbox)

flexbox 悬空根因:列 `flex-start` 顶对齐,矮柱整列挤顶部。可以用 `justify-content:
flex-end` 修,但还得手搓 Y 轴刻度、网格线、千位分隔 —— 都是 ECharts 现成的,且
"资产增长"图已用同一套 `LazyECharts`。换 ECharts 一次解决全部,视觉语言统一。
本地 `HistogramBars` 是组件私有,替换不影响 CYB-4294 批量查页。

## 为何 P50/P90 不做精确竖线

markLine 精确竖线需要**连续数值 X 轴**(按 ms 定位)。本图 X 轴是**分类轴**(10 个
离散桶),竖线只能吸附到桶边界、无法落在"15m44s"精确位置。真做需把 X 轴改连续、
桶按真实 ms 宽度画,是更大重构。折中"高亮 P50/P90 落入的桶"列为 follow-up。

## 契约兼容性

`buckets` 数组元素 schema 不变(label/lo_ms/hi_ms/count/total_ms),只是**长度 5→10、
label 取值变**。前端 `data.buckets.map` 动态渲染,天然兼容;任何硬编码 5 桶的消费方
需同步(仓库内仅 dashboard 卡消费,已适配)。
