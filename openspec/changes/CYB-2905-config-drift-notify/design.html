Pipeline 配置版本漂移通知

CYB-2905 · 起草 2026-07-01 · Rick · UI 与现有 DataBrew 风格一致
Backend Frontend Feature Draft

TL;DR

用户 a 改了 PipelineConfig（algorithm hyperparameters / threshold / 规则文件）v1 → v2，所有依赖该 config 的 b 的 batch 在下次部署时静默升级。dev 实测所有 batch 的 pipelineJSON.nodes 都没有 runtimeConfig block（frontend pipeline-designer 未暴露），DeployPanel 默认 version ?? currentVersion 静默 follow latest。b 完全无感知，出现复现性丢失 + 资源浪费 + 信任成本。

本设计目标：让 b 在 a 改 config 时立刻看到影响，并在明确 ops surface 上主动选择升级 / 忽略。

用户 & Use Cases

IDActorGoal（user 视角）入口

UC-5Cora（平台管理员）"全平台有哪些漂移没人管"Drift 总览 /admin/drift

核心机制（5 步）

L层做什么
1事件捕获PipelineConfig.CreateVersion 后 → emit outbox event
2反查受众run_inputs.ref_id=X AND ref_version<N → group by owner
3drift 表每 affected user 一行 status=pending
4推送飞书群 @mention + dashboard API
5用户反应Bump / Ignore / 一键 Bump all

Status 状态机

  created  ──→  pending  ──→ (Bump) ──→  bumped
           └──→ (Ignore) ──→  ignored
           └──→ (Auto Bump) ──→  auto_bumped   ← [Phase 3+ 不做]

drift 记录不会物理删除，只更新 status。后续查询"曾经有什么 drift"仍能看到历史。

关键交互 & 异常 fallback

场景fallback用户感受
飞书推送失败notified_at IS NULL，留给 cron 重试登录 dashboard 仍可见
同 user 同一 config 短时间多次 drift（CI auto-publish）drift_event_id UNIQUE（5 分钟窗口去重）不会刷屏
Bump 后 run_inputs ref_version 写新值失败drift 状态保持 pending，用户可以重试无副作用（run 还是用旧版）
config 被归档（lifecycle=archived）drift 标 archived_out，不在主列表不再推送

关键交互细节

方式效果适合
Bump 单条写 run_inputs.ref_version = latest，下次部署用新参数少量 batch、有选择
一键 Bump 全部同 config 下的所有 affected batch 一起升信任度高、想全升
Ignoredrift 状态置 ignored；后续同 config 不再给此 user 推明确不受影响
迁移到 template（M2+）写 runtimeConfig 到 template 节点 — 长期 fixowner 想强制所有人用新参数

实施 Roadmap（3 Phase）

Phase范围用户能做什么≈ sprint
1 数据基础migration 060 + outbox emit + 反查 SQL + drift API（开发者查表，UI 未接）0.5
2 Dashboard + 操作Drift sub-tab + 详情页 + Bump/Ignore API登录 → 看 drift → 点 Bump 升级0.5
3 飞书推送subscriber → webhook + cron 摘要飞书群被 @ 提醒0.5

总估 1 ~ 1.5 sprint。Phase 1 跑通后就能在 DB 看见数据正确。

明确不做

  • ❌ 自动 bump（auto_bump） — 用户没主动确认，绝不自动升级 batch 参数
  • ❌ 飞书 DM 个人推送 — 依赖额外权限（tenant_access_token + open_id），ROI 低
  • ❌ 强制 pipeline-designer 暴露 runtimeConfig — 本方案 advisory，不强改 UX（后续 PR 可加）
  • ❌ drift 自动删除 — 只标 status，保留审计链路

技术要点（摘要）

具体 schema / API / 代码实现放在 Phase 1 起 PR 时写，本设计锁定 5 层 + 反查路径：

  • 触发：PipelineConfig.CreateVersion 后 → outbox event pipeline_config_version_published
  • 反查：run_inputs.ref_id=X AND ref_version<N GROUP BY owner
  • drift 表：UNIQUE (event_id, config_id, user_email) 去重
  • 推送：飞书 webhook (group chat) + dashboard API；不 DM
